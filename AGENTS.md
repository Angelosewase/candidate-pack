# AGENTS.md — Dataset Request Desk

Two-app repo, no root tooling. `backend/` (FastAPI + PostgreSQL) and `frontend/` (Next.js + pnpm) are independent — no shared workspace config. Single git repo: commit everything (including `frontend/`) from the repo root. CI (`.github/workflows/tests.yml`) runs backend pytest (needs the `postgres` service on 55432) plus frontend typecheck/lint/build.

## Run

Full stack (db + migrations + seed + api + ui), from repo root:

```bash
docker compose up --build
# backend http://localhost:8000, frontend http://localhost:3000, db localhost:5432
```

Backend entrypoint `backend/app/main.py`. Container startup order matters: `alembic upgrade head` → `python3 -m app.cli --users ../seed/users.json` → `uvicorn`. Run Alembic from `backend/` (relies on `prepend_sys_path = .` in `alembic.ini`).
Config is env-only via `backend/app/config.py` (`DATABASE_URL`, `JWT_SECRET` required in production, `LOG_LEVEL`, `MAX_IMPORT_BYTES`=50MB). Frontend talks to `NEXT_PUBLIC_API_URL` (defaults to `http://localhost:8000` in `docker-compose.yml`).

Seed logins (password `ops123` for all): `admin@example.com`, `ops1@example.com`, `ops2@example.com`, `client-a@example.com`, `client-b@example.com`.

## Test / verify

Backend tests need a **separate live Postgres** `desk_test` on `localhost:55432` — hardcoded in `backend/tests/conftest.py`, *not* the compose DB on 5432. No sqlite fallback.

```bash
cd backend
pip install -r requirements-dev.txt  # pytest lives here, not in requirements.txt
python3 -m pytest tests/ -x -q
python3 -m pytest tests/test_workflow.py -q  # single file
```

No backend lint/typecheck config. Frontend (run in `frontend/`, uses **pnpm**, not npm): `pnpm run typecheck`, `pnpm run lint`, `pnpm run build`. Next.js 16 rules in `frontend/AGENTS.md` are auto-generated by `next dev` — leave that block alone.

## Architecture notes agents miss

- Business logic lives in `backend/app/services/` (`requests.py`, `assignments.py`, `importer.py`, `analytics.py`, `users.py`); routers in `backend/app/api/` are thin. Put rule changes in services.
- Status machine source of truth is `backend/app/workflow.py` (`TRANSITIONS` table: staff own `submitted→in_progress→delivered` and `rejected→in_progress`; clients own `delivered→accepted/rejected`). DB-level preconditions (e.g. episode count before `delivered`) are in `services/requests.py`.
- Auth: JWT Bearer (`app/deps.py` `require_roles`); user is re-fetched from DB per request so deactivation/role change is immediate. Client accessing another client's request returns **404, not 403** (anti-probing) — don't "fix" this or assert 403.
- Double-assignment is guarded by a Postgres partial unique index (`assignments(episode_id) WHERE released_at IS NULL`) → catch `IntegrityError` as 409. Never rely on read-then-write checks.
- Real-time is SSE over Postgres `LISTEN/NOTIFY` (`app/events.py`, channel `request_events`); `pg_notify` runs inside the mutating transaction so rolled-back changes emit nothing. No Redis; per-process `Broker` fan-out tolerates multiple workers.
- CSV import is a blocking HTTP request capped at 50MB; idempotent upsert via `ON CONFLICT` in `services/importer.py`. Messy-input expectations are in `seed/README.md`.
- Observability: `GET /health`; one structured log line per request (method/path/status/duration/user_id) via `AccessLogMiddleware`.
- Analytics (`services/analytics.py`) must stay as in-DB aggregations (`GROUP BY`, `percentile_cont`), not Python-side loops.
